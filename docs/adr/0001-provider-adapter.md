# ADR-0001 — Market data behind a provider interface

- **Status:** Accepted
- **Date:** 2026-10-14
- **Deciders:** application architecture
- **Supersedes:** —

---

## Context

The product needs historical pricing and sales data for a catalogue of sneakers, aggregated across
resale marketplaces. The obvious sources are commercial aggregators (KicksDB fronts StockX and GOAT),
and the obvious first implementation is a client that calls one of them directly from the places that
need data.

Three forces make that naive approach untenable:

1. **Metered quotas.** The free tier of the chosen aggregator is 1,000 requests per month. A demo, a
   CI run and a test suite that each touch the network will exhaust that within days, after which the
   application renders empty states to anyone who opens it.

2. **Determinism.** The Trend Momentum Index has a 52-case test suite asserting direction and boundary
   behaviour. Asserting a numeric property against a live endpoint whose answers change hourly is not
   a test; it is a flaky integration check wearing a unit test's clothes.

3. **Source volatility.** Aggregator APIs change shape, change pricing and disappear. Committing the
   application to one vendor's response format means a rewrite when that happens.

## Decision

Introduce a `MarketDataProvider` interface. The application depends only on the interface.

```ts
interface MarketDataProvider {
  readonly id: string;
  readonly label: string;
  readonly capabilities: ProviderCapabilities;   // declared, so callers degrade gracefully
  searchProducts(query, options?): Promise<NormalizedProduct[]>;
  getProduct(id): Promise<NormalizedProduct | null>;
  getPriceHistory(productId, range?): Promise<PriceObservation[]>;
  getSalesHistory(productId, range?): Promise<SalesObservation[]>;
  getQuota?(): ProviderQuota;
}
```

Two implementations ship:

- **`fixture`** — reads a committed snapshot in `fixtures/`. **This is the default.**
- **`kicksdb`** — calls the live KicksDB v3 API with a bearer key, with exponential backoff and
  quota capture from the `X-Quota-Current` response header.

Selection is by environment variable (`SOLEINDEX_PROVIDER`), with no code change:

```
SOLEINDEX_PROVIDER=fixture   # default: offline, deterministic
SOLEINDEX_PROVIDER=kicksdb   # live, metered, requires KICKSDB_API_KEY
```

Three supporting decisions:

1. **The snapshot is generated by a committed, seeded generator** (`scripts/generate-fixtures.ts`,
   seed `20261014`). Regenerating produces a byte-identical output. The snapshot is data, not a
   mock: the application reads it through the same interface and materialises it into the same
   tables a live pull would populate.

2. **`capabilities` is part of the contract.** A caller can ask whether a provider reports sales
   history, whether it is metered, and how far back it goes, and adapt — instead of discovering a
   limitation through a thrown error mid-render.

3. **Normalisation happens at the provider boundary.** The KicksDB adapter maps free-text colourway
   strings onto normalised colour keys with a conservative vocabulary lookup that returns `unknown`
   rather than guessing. A mis-tag shows up as a visible data-quality gap instead of a silent
   miscategorisation in the trend intelligence.

## Consequences

### Positive

- **The demo cannot break.** No API key, no network, no quota. `git clone && pnpm install && pnpm dev`
  produces a fully populated application.
- **The test suite is a test suite.** 52 assertions in 7 ms, no network, no flake.
- **A third source is a new file, not a refactor.** Adding `ebay`, `keepa` or an internal warehouse
  means implementing six methods.
- **The switch to production data is an environment variable**, which means it can be exercised in
  staging without a code branch.
- **The generator is a specification.** Writing it forced every derived quantity — the market index,
  the attribute share series, the category aggregates — to be defined precisely, and its output is
  the fixture the tests and the demo both use.
- **`--dry-run` de-risks the live adapter.** `pnpm ingest --provider=kicksdb --dry-run` exercises the
  request path and prints the decoded payload without writing, which is how a response mapping can be
  confirmed against a real plan.

### Negative

- **The snapshot can drift from reality.** A reader might mistake the synthetic figures for market
  data. Mitigated by stating the synthetic status in the README, in the application footer on every
  page, and in the snapshot manifest itself.
- **Two implementations to maintain**, one of which is a code path only exercised by the generator.
- **The interface constrains query shape.** A provider offering something the interface does not
  model — order-book depth, for example — cannot be surfaced without extending the contract. Accepted:
  extending one interface is cheaper than the coupling it prevents.
- **The fixture snapshot is ~870 KiB of JSON in the repository.** Large for a repo, small for a
  dataset. The alternative — generating at install time — removes reproducibility for anyone
  checking out without running a build step.
- **The live adapter is unverified.** No KicksDB account was available, so `kicksdb.ts` has never
  executed a real request. Endpoint shapes follow the published v3 reference. This is recorded in the
  README's honest-status table rather than glossed over.

## Alternatives considered

| Alternative | Rejected because |
| --- | --- |
| Call the aggregator directly from each page | No caching, no rate limiting, no quota visibility, and the test suite becomes non-deterministic |
| Record HTTP fixtures with a cassette library | Ties the tests to one vendor's response format — exactly the coupling the interface exists to prevent — and cassettes rot silently |
| Use a mock service worker | Tests a mock, not a normaliser. The value here is the normalisation layer, which MSW would bypass |
| Ship with no data and require the user to supply a key | Nobody evaluates a dashboard with an empty state. The demo has to work first, which is the entire argument |
| Generate fixtures at install time instead of committing them | Reproducibility requires the same seed *and* the same dependency versions *and* the same runtime. A committed artefact has none of those dependencies |

## Verification

```bash
pnpm fixtures:generate   # deterministic; re-running produces identical bytes
pnpm test                # 52 tests, no network access
pnpm ingest --dry-run    # exercises the request path, writes nothing
pnpm db:reset            # full rebuild from the snapshot in ~5 s
```
